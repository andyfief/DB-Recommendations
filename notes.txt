The LLM generating the delta needs to know your vector schema explicitly — the column names, and crucially the scale. If sweet ranges 0–1 and the drink is already at 0.7, a +0.5 delta overshoots into a clamped or nonsensical region. You'd want to either pass the current drink's vector values to the delta-generating LLM so it can generate a contextually reasonable shift, or normalize post-aggregation before querying.
